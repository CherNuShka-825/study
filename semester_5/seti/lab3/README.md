# Лабораторная работа №3 — Места (Асинхронное сетевое взаимодействие)

Приложение на Go для поиска географических объектов, получения текущей погоды и сведений о достопримечательностях поблизости. Запросы к внешним API выполняются асинхронно, а их результаты объединяются в один отчёт.

Доступны графический интерфейс на Fyne и консольный режим.

## Возможности

- Поиск локаций по названию через **GraphHopper** (данные OpenStreetMap).
- Необязательная фильтрация по типу объекта: тип вводится на русском языке и преобразуется в OSM-тег.
- Выбор локации из списка результатов поиска.
- Получение погоды через **OpenWeatherMap**: температура, ощущаемая температура, влажность, давление, ветер и погодные условия.
- Поиск географически привязанных статей **Wikipedia** в выбранном радиусе (от 1 до 10 000 м; по умолчанию — 3000 м).
- Получение кратких текстовых описаний статей и ссылок на миниатюры.
- Загрузка изображения в GUI при выборе места, отдельно от формирования отчёта, с кэшированием уже загруженных изображений.
- Обработка частичных ошибок: отсутствие погоды не мешает показать найденные места, и наоборот.
- Отмена выполняющихся запросов.

## Технологии

| Компонент | Назначение |
| --- | --- |
| **Go** | Язык программирования, горутины, каналы и `context` |
| **GoFetch** | HTTP-запросы через асинхронный `GetAsync()` |
| **RxGo v2** | Асинхронные цепочки и объединение результатов API |
| **Fyne v2** | Графический интерфейс |
| **GraphHopper API** | Геокодирование и поиск локаций |
| **OpenWeatherMap API** | Погода по координатам |
| **MediaWiki API** | Географический поиск статей Wikipedia, описания и миниатюры |

## Подготовка

Необходимы Go, доступ к интернету и системные библиотеки для сборки Fyne (графические библиотеки OpenGL/X11 и инструменты компиляции C, если используются в текущей конфигурации).

Приложению нужны два API-ключа: **GraphHopper** и **OpenWeatherMap**. Кроме того, для запросов Wikimedia используется строка **User-Agent**. Эти значения представлены структурой `api.Keys`:

```go
type Keys struct {
    GraphHopper        string
    OpenWeather        string
    WikipediaUserAgent string
}
```

Укажите реальные значения в конфигурации запуска проекта. Для Wikipedia отдельный API-ключ не требуется.

## Использование

1. Введите название локации. При необходимости укажите её тип; пустое поле означает поиск без фильтра по типу.
2. Нажмите **«Найти локации»** и выберите подходящий результат.
3. Укажите радиус поиска интересных мест в метрах: от **1** до **10 000** (по умолчанию **3000**).
4. Нажмите **«Получить информацию»**. После завершения запросов появится отчёт с погодой и найденными статьями Wikipedia.
5. В GUI выберите интересное место из списка, чтобы увидеть описание, ссылку на статью и, при наличии, фотографию.

В консольном режиме те же данные выбираются последовательным вводом ответов. Результат выводится целиком после формирования отчёта.

> Поиск интересных мест использует статьи Wikipedia с географическими координатами, поэтому не все реальные объекты обязательно присутствуют в результатах.

## Асинхронная обработка

В проекте разделены два уровня:

- **`internal/api`** выполняет HTTP-запросы и возвращает `rxgo.Observable`.
- **`internal/service`** связывает независимые и зависимые запросы, обрабатывает ошибки и выдаёт `Future[T]` — канал с одним итоговым результатом или ошибкой.

Схема формирования отчёта:

```text
                       BuildReportAsync()
                              │
                ┌─────────────┴─────────────┐
                ▼                           ▼
         WeatherAsync()                PlacesAsync()
          (OpenWeather)             (Wikipedia geosearch)
                │                           │
                │                           ▼
                │                  []PlaceSummary (PageID)
                │                           │
                │                           ▼
                │                 PlaceDetailsAsync()
                │                  для каждой статьи
                │                           │
                └─────────────┬─────────────┘
                              ▼
                         models.Report
                              │
                              ▼
                       Future[Report]
                              │
                              ▼
                         GUI / Console
```

Погода и поиск статей выполняются независимо и одновременно. Запросы подробностей зависят от `PageID`, полученных при географическом поиске. Результаты объединяются операторами RxGo (`Map`, `FlatMap`, `ZipFromIterable`, `OnErrorReturn`) без блокирующего ожидания промежуточных ответов.

Изображения **не входят в основную цепочку отчёта** и загружаются в GUI отдельно через `LoadImageAsync()`.

## Ограничения и обработка ошибок

- **30 секунд** — максимальное время формирования отчёта.
- **3 секунды** — максимальное время отдельной загрузки изображения.
- **12 секунд** — тайм-аут HTTP-клиента GoFetch на запрос.
- **2** — максимальное число одновременно выполняемых запросов описаний статей Wikipedia.
- **1 МиБ** — максимальный размер JSON-ответа; **2 МиБ** — изображения.
- Некорректные результаты геокодирования пропускаются; ошибки отдельных описаний сохраняются в соответствующих элементах.
